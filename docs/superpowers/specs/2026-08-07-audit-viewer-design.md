# Audit Viewer and Pending Color Design

## Context

Branch staff use `AuditCkDayo/Views/Audits/BranchVerifyList.cshtml` to verify delivered audit items. Managers and owners use `AuditCkDayo/Views/Audits/VerifyList.cshtml` to approve or reject audits after branch verification. Both screens already show a cropped receipt preview and audit line items in a side inspector, but users cannot view the complete receipt image or a full audit summary in one focused surface.

The current pending status color reads as harsh yellow/amber in badges and counters. It should be replaced with a calmer color that fits the existing dark navy and slate theme.

## Visual Direction

Use a restrained operational theme: navy, slate, soft blue, and muted indigo. Pending states should feel calm and professional, not warning-like. Replace warm amber emphasis with a theme-aligned muted blue.

Pending color tokens:

- `audit-pending`: `#3B5B92`
- pending backgrounds: `bg-audit-pending/10`
- pending borders: `border-audit-pending/20`
- pending text: `text-audit-pending`

This keeps pending states distinct from success green and error red while matching the existing primary/secondary palette.

## Feature Design

Add a shared full-screen audit viewer pattern to both verification views.

Each view gets a `View Full Audit` button in the current side inspector. The button opens a modal overlay without leaving the queue page.

The modal shows:

- full receipt image with `object-contain` so the whole receipt is visible
- buyer name
- establishment
- transaction date
- amount
- description
- notes
- receipt line items table

The modal does not submit approve/reject actions. Existing approve/verify/reject buttons remain in the inspector so the action flow stays unchanged.

## Data Flow

Both queue rows already carry the data needed for selection through `data-*` attributes:

- audit id
- buyer
- establishment
- amount
- description
- notes
- line item details JSON
- receipt URL

The modal should reuse those attributes and update when `selectAudit(row)` runs. The currently selected row is the source of truth for the modal content.

The receipt image uses the existing authorized receipt URL generated by `AuditsController.Receipt`, so existing access rules remain unchanged.

## Accessibility and Interaction

- Modal opens from `View Full Audit`.
- Modal closes from a close button, Escape key, or backdrop click.
- The receipt image uses `object-contain` on a dark/surface background.
- The modal has `role="dialog"`, `aria-modal="true"`, and a labelled title.
- Long line-item lists scroll inside the modal body.

## Testing

Add regression tests that verify both verification views render the full audit viewer controls. Existing controller authorization tests for receipt access remain the backend coverage for receipt image security.

Run targeted tests first, then the full test suite in Release configuration because Debug output may be locked by a running local app process.
